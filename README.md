# Codex Team Kit

Готовый набор для стандартизации разработки с OpenAI Codex: правила проекта,
четыре переиспользуемых навыка (skills), TypeScript-демо со строгой типизацией,
тесты, CI и методика оценки работы агента.

Проект подготовлен как портфолио.

## Быстрый старт

Понадобятся **Node.js 22 или новее** и **npm**. Выполните в папке проекта:

```sh
npm ci
node scripts/install-skills.mjs
npm run verify
npm run demo
```

Установщик копирует четыре навыка из `skills/` в `.agents/skills/` и отказывается
перезаписывать уже существующие навыки. Для установки нужен доступ на запись
в эту папку. Если среда Codex ограничивает такой доступ, выполните команду
установки в обычном терминале.

**Если вы распаковали ZIP-архив проекта**, папка `.agents/skills/` уже включена
в него — пропустите команду `node scripts/install-skills.mjs`.
После установки откройте новую сессию Codex в папке проекта.

Версии зависимостей зафиксированы в `package-lock.json`. Особенности его
восстановления без сети и ограничения проверки на других платформах описаны
в [отчёте о проверках](docs/verification.md).

## Что входит в проект

- `AGENTS.md` — правила планирования, реализации, тестирования, безопасности и передачи результата.
- `PLANS.md` — шаблон плана для сложных изменений; соглашение команды.
- `skills/` — исходники навыков `review-changes`, `write-tests`, `security-audit` и `verify-project`.
- `demo/` — обработка заявок с проверкой входных данных и допустимых переходов между статусами.
- `.github/workflows/ci.yml` — проверки кода, типов, тестов, сборки и детерминированных сценариев в GitHub Actions.
- `evals/` — примеры кода с дефектом и без него, сценарии и критерии оценки агента.
- `docs/` — упражнение по изменению кода, методика оценки, результаты проверок и материалы для отклика.

## Команды проекта

```sh
npm run lint       # Проверка кода с ESLint
npm run typecheck  # Проверка типов TypeScript
npm test           # Запуск тестов Vitest
npm run build      # Сборка в папку dist/
npm run eval       # Детерминированные проверки; требуется выполненная сборка
npm run verify     # Все проверки последовательно, включая сборку перед eval
npm run demo       # Сборка и запуск демонстрационного примера
```

Команда `verify` останавливается при первой ошибке. Проверки, до которых
выполнение не дошло, нельзя считать пройденными.

## Как использовать навыки

Откройте Codex в папке проекта и отправьте нужный запрос:

```text
Используй $review-changes для ревью моих текущих изменений.
```

```text
Используй $write-tests, чтобы добавить регрессионные тесты для изменённого поведения.
```

```text
Используй $security-audit для проверки валидации входных данных и разрешений CI.
```

```text
Используй $verify-project: запусти все проверки и сообщи фактические результаты.
```

Результат ревью — конкретные замечания, упорядоченные по серьёзности. Для каждого
указываются файл и строка, условия возникновения ошибки, последствия и способ
исправления. Если дефекты не найдены, агент сообщает об этом и обозначает
ограничения проверки. Навыки ревью и аудита не изменяют файлы.

## Демонстрационный сценарий

1. Выполните `npm run verify` и изучите `demo/src/tickets.ts`.
2. Попросите Codex выполнить задание из [docs/safe-change.md](docs/safe-change.md), используя `$write-tests`.
3. Проверьте, что регрессионный тест падает до исправления и проходит после него.
4. Запустите `$review-changes` и `$security-audit`, затем самостоятельно просмотрите изменения.
5. После публикации репозитория создайте pull request и проверьте фактический результат GitHub Actions.

В базовой версии заявки проходят путь `open → in_progress → resolved`.
Также разрешён возврат `in_progress → open`. Статус `resolved` является конечным.
Задание для демонстрации — добавить переход `resolved → open`, сохранив остальные
правила и покрыв изменение тестами.

Некорректные входные данные и запрещённые переходы вызывают ошибки класса
`TicketError`. Изменение статуса возвращает новый объект, не меняя исходный.
В демо нет базы данных, авторизации и HTTP-сервера: оно показывает бизнес-логику
и процесс разработки с агентом.

## Проверка результатов и ограничения

Фактические результаты локальных запусков приведены в
[docs/verification.md](docs/verification.md). Включённая конфигурация CI
сама по себе не подтверждает успешный запуск GitHub Actions.

Команда `npm run eval` проверяет контракты приложения и структуру файлов навыков.
Она **не оценивает качество работы AI** и не доказывает, что Codex загрузил
навык и выполнил его инструкции.

Порядок независимого запуска агента, сохранения трасс и оценки результатов
описан в [docs/evaluation.md](docs/evaluation.md). Для проверки используются
как пример с известным дефектом, так и корректный код — это позволяет учитывать
ложные замечания. Без измерений проект не заявляет прирост производительности,
экономию времени или точность AI-ревью.

AI-ревью дополняет автоматические тесты и решения человека по архитектуре
и продуктовому поведению.

## Перенос в другой репозиторий

Скопируйте `AGENTS.md` и нужные каталоги навыков в `.agents/skills/` целевого
репозитория. Адаптируйте команды проверки и требования к его бизнес-логике,
затем проверьте навыки на примерах с ошибками и без них.

Сохраняйте соглашения целевого проекта. Правила обработки заявок из этого демо
не нужно переносить в несвязанные проекты. Инструкции навыков должны оставаться
короткими и соответствовать конкретным задачам.
